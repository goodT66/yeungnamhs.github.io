# 비공개 시트 전환 배포 게이트 (2026-11-17)

현재 **실제 서버 배포·시트 권한 변경은 하지 않았음**. 아래 검증 전에는 기능 플래그를 켜거나 시트를 제한됨으로 변경하지 말 것.

## 반드시 해결할 보안 문제
1. 기존 Apps Script의 인증 없는 doGet()은 3학년감독표를 반환함. 기존 호출처를 새 Firebase 조회로 옮긴 후 doGet을 인증 없는 데이터 반환이 불가능하도록 수정하고 **새 버전 배포**.
2. 별도로 배포된 감독표 Apps Script(SUPERVISOR_SHEET_API_URL)도 공개 데이터 반환 여부 점검. GitHub index.html만 변경해도 외부 배포 URL은 계속 노출될 수 있음.
3. Firebase getTeacherSheet의 교사 이메일 허용 목록을 서버에 안전하게 설정하고, Apps Script의 SUSI_ALLOWED_EMAILS와 동일한 교사 권한을 사용. 환경 변수가 비어 있으면 기본 거부.
4. Apps Script doPost에서 getTeacherSheet도 **verifySusiTeacher_ 실행 후에만** 처리하도록 순서 검증. 허용되지 않은 sheetKey 거부.
5. 서버 함수가 실제 배포된 후 비인가 사용자/로그아웃 상태에서 호출이 거부되는지 확인. 로그인 UI만 숨기는 것은 접근 제어가 아님.
6. 사용자가 로그아웃하거나 교사 계정을 변경할 때 메모리에 남은 성적/학생/졸업생 자료 및 진행 중인 조회를 정리해야 함. 현재는 UI 숨김 위주이므로 추가 구현·검증 필요.
7. 개인정보가 들어간 Google Sheets의 '웹에 게시' 공개 링크/CSV/gviz 공유 설정도 모두 점검. 공유를 제한해도 기존 게시된 웹 데이터는 별도 해제해야 할 수 있음.

## 안전한 순서
1. Apps Script에 교사 전용 getTeacherSheet 분기를 추가하고 새 배포 버전을 생성.
2. Firebase 함수에 동일한 서버측 허용 목록과 URL을 연결하여 배포.
3. 별도 테스트 환경에서 기능 플래그 활성화 및 전체 회귀 테스트.
4. 공개 doGet과 별도 감독표 배포 경로의 무인증 데이터 응답 차단.
5. 사이트 브랜치 병합 및 교사 로그인 테스트.
6. 마지막에 Google 시트 공유 설정을 '제한됨'으로 변경하고 기존 게시 링크도 해제.
7. 제한 상태에서 재시험. 문제가 생기면 먼저 사이트를 되돌리고 시트 권한은 보안 담당자와 상의해 복구.

## 현재 구현의 제한
- feature 브랜치의 index.html에서 ENABLE_PRIVATE_SHEETS=false.
- 기존 공개 fetch 경로는 플래그가 false인 동안 유지됨.
- 실제 Firebase/Apps Script 배포 및 테스트는 이 저장소만으로 실행할 수 없음.
- 서버 함수의 실제 변수명과 Apps Script 응답 헬퍼는 기존 배포 소스에 맞춰 통합해야 함.
